# ゲームオーバー画面 設計ドキュメント

- 作成日: 2026-07-04
- 対象: `gameover.png` を用いたゲームオーバー画面（原作準拠：死亡＝即オーバー）
- 前提: タイトル/ステージ選択/3ステージ/クリア記録/ボタン画像化/進捗バーまで実装済み

## 目的

現 Web 版は「死亡＝その場でチェックポイント即復帰（無限リトライ）」だが、原作は死亡で `GameOverSubMode`（暗転→`gameover.png`＋ボタン）を表示していた。原作準拠で、死亡時にゲームオーバー画面を出す。

## 契機

死亡（壁激突／落下／針接触／敵の横接触＝既存 `die()` の全経路）で即ゲームオーバー。現在の「即その場復帰＋赤フラッシュ」は廃止。

## 演出とフロー

1. 死亡 → `isEnded=true`（`update()` の移動/死亡判定を停止）、プレイヤー停止。
2. 半透明の黒（`Rectangle`）を ~300ms でフェードイン（暗転、depth 90）。
3. フェード完了後、`gameover.png`（420×420, 中央, scale 0.7, depth 100）＋ボタン2つ（`button_large`）を表示：
   - **リトライ**：チェックポイント（通過済みの中間ゲート、無ければスタート）から再開。
   - **ステージ選択へ**：`StageSelect` へ。

## リトライ（チェックポイント引き継ぎ）

`scene.restart({ stageIndex, resumeX, resumeY, usedGate })` で再開する。`restart` により敵・UI・タイルマップは自然に再生成され、`init()` が resume 情報を受け取って `create()` がプレイヤーを resume 座標にスポーンする。

- `init(data)`：`resumeX/resumeY` があればそれを初期スポーン＋チェックポイントに、無ければスタート。`usedGate` も引き継ぐ（ゲート通過後に死んだら再開後も gateless 扱いにしない）。
- ゴール（クリア）時の「リトライ」は従来どおりステージ最初から（resume 無しで restart）。

## 変更点（整理）

- `die()`：チェックポイント即復帰＋赤フラッシュ＋`respawnEnemies()` を廃し、ゲームオーバー表示に変更。
- `respawnEnemies()`：死亡が restart 経由になり不要になるため削除（敵リセットは restart で担保）。
- クリア演出 `showResult()` はそのまま維持。

## スコープ

### 含む
- 死亡時のゲームオーバー画面（暗転＋`gameover.png`＋リトライ/ステージ選択）、チェックポイント引き継ぎリトライ。

### 含まない
- 残機表示、スコア、BGM/SFX、到達率の永続化。

## テスト方針

- Playwright: 死亡で暗転→`gameover.png`＋2ボタン表示、リトライでチェックポイント（スタート/ゲート）から再開、ステージ選択へ遷移。ゲート通過後の死亡→リトライがゲート位置から始まること。
- 既存ユニットテスト（stages/Progress/loaders）に影響なし。
